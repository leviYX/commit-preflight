---
name: preflight
description: 检查本次暂存提交的行数、规模与常见风险，按需运行项目检查。
---

对当前 Git 仓库执行提交前检查：

1. 确定项目绝对路径，调用 scan_changes，默认 scope=staged。统计以工具返回值为准，不自行估算。
2. 清楚报告：暂存文件数、新增行、删除行、总变更行、计入阈值的变更行、排除文件、二进制文件、未跟踪文件与当前阈值。总变更行是新增+删除，不是净增，也不等于有效代码行数。
3. 按错误、警告列出文件和行号；疑似凭据不回显原始内容。规则扫描可能误报，需结合上下文核实。忽略的文件没有被内容扫描。
4. availableChecks 只是发现的脚本，不代表执行成功。用户已要求运行检查时，再通过 run_project_check 显式传入可用检查名；禁止 deploy/build/install、任意 shell 或自动安装依赖。
5. 脚本检查读取工作区，不是隔离的暂存快照；部分暂存时必须说明这一限制。输出未返回时，可以建议用户在本地执行工具列出的命令查看详细错误。
6. 最后给出“通过 / 需关注 / 未通过 / 无暂存变更”，明确哪些检查实际运行、哪些未运行。无暂存变更不能说“代码检查通过”。不要自动 git add、commit 或修改配置绕过门禁。

如果工具尚未注册，报告集成缺失，不编造检查结果。此命令只指导检查，不自动修改项目。
