# DSH Commit Preflight — 提交前检查插件

用于回答“这次提交改了多少行、规模是否过大、有没有明显残留问题”。在 DSH 图形界面中选择项目，输入 `/preflight` 即可检查。需要 Node.js >=22 和 Git，当前版本面向 macOS / Linux。

插件旨在实现对于提交的检查，避免一次代码过于庞大导致的无法审核进而使工程腐化。


## 已实现

- 默认检查 **Git 暂存区**，对应下一次普通 `git commit`，不把未暂存或未跟踪文件混进来。
- 全量和计入策略的文件数、新增行、删除行、总变更行；逐文件统计；识别重命名和二进制文件。
- 可配置规模阈值，默认 **>300 行警告、>800 行失败、>20 个文件警告**，这些不是你公司的正式规定。
- 只扫描新增内容：冲突标记/未合并暂存区、debugger、console.log、TODO/FIXME、部分常见凭据格式和硬编码凭据。冲突/疑似凭据为错误，其他为警告。结果只包含位置和说明，不返回源码片段或凭据值。
- 发现并按需运行 package.json 中的 lint、typecheck、type-check、check、test，保留退出码、超时和输出超限状态。
- 提供 `/preflight` 命令，以及供 DSH AI 调用的三个检查工具。

## 安装到 DSH

以下方式已在 `@deepseek-ai/dsh 0.1.0-rc.6` 验证。无需知道 DSH 安装目录。

1. 保存完整插件目录，例如 `/Users/livi/plugins/commit-preflight`。
2. 在终端执行一次安装命令，把路径换成你自己的插件目录：

   ```sh
   npx @deepseek-ai/dsh plugin --profile web add "/Users/levi/plugins/commit-preflight"
   ```

3. 退出原来的 DSH 进程，再启动：

   ```sh
   npx @deepseek-ai/dsh web
   ```

`web` 是图形界面使用的 profile。若你使用其他 profile，请替换成对应名称。安装后请保留插件目录，勿随意移动。仅把目录放进 plugins 文件夹不会自动启用插件。

## 在图形界面中使用

1. 打开 DSH 图形界面，在输入框上方的项目选择器中选择要检查的项目，例如 `shop-app`。
2. 使用平时的 Git 工具或编辑器，将准备提交的文件加入暂存区。**暂存区就是本次准备提交的内容**，不是所有尚未提交的修改。
3. 在 DSH 输入框中输入并发送：

   ```text
   /preflight
   ```

插件自动使用当前会话选择的项目，并在界面返回检查报告，无需重复填写项目路径。该命令检查规模和新增内容，不调用模型，也不运行 lint/test。

### 怎么看结果

| 报告中的 status | 含义 | 建议 |
| --- | --- | --- |
| `pass` | 未发现当前规则覆盖的问题 | 结合正常审查流程决定是否提交 |
| `warn` | 发现规模警告或代码残留等提醒 | 查看 findings，确认或处理后再提交 |
| `fail` | 规模超限、冲突或疑似凭据等错误 | 处理问题后重新检查 |
| `empty` | 暂存区没有变更 | 确认选对项目，并暂存准备提交的文件 |

报告包含新增行数、删除行数、总变更行数、文件数及具体问题位置。**总变更行数 = 新增 + 删除**，例如新增 150 行、删除 80 行，提交规模为 230 行。检查只生成报告，不会自动提交代码或拦截提交。

### 临时检查另一个项目

通常只需 `/preflight`。如果想临时检查其他项目，可以在同一个 DSH 输入框中发送：

```text
/preflight /Users/zhang/projects/another-project
```

显式路径会覆盖当前项目选择；请使用绝对路径，路径含空格时无需引号。没有选择项目且没有提供路径时，插件会提示先选择项目，不会检查 DSH 启动目录。

### 需要运行 lint 和 test 时

`/preflight` 不会自动执行项目脚本。如果还需要脚本检查，在 DSH 对话中告诉 AI：

> 对 /Users/zhang/projects/shop-app 做提交前检查，并运行项目已有的 lint 和 test 脚本。

将示例路径换成实际项目路径。AI 可调用插件的 `run_project_check` 工具执行已有脚本；插件不会自动安装依赖。脚本运行的是工作区内容，可能生成缓存或文件。如果文件只有部分修改被暂存，脚本通过不代表暂存快照也通过。

## 公司规则配置

规则文件放在**要检查的项目**里。例如，你在 DSH 中选择的商城项目是 `/Users/zhang/projects/shop-app`，就把规则放在这个项目最外层目录。

在编辑器或文件管理器中，将插件目录里的 `.dsh-preflight.example.json` 复制到商城项目，并重命名为 `.dsh-preflight.json`；也可以直接在商城项目最外层新建同名文件，粘贴下面的 JSON 示例。

“仓库根目录”就是 Git 项目的最外层目录，通常与 `.git` 位于同一层。文件名以点开头，文件管理器中可能需要先开启显示隐藏文件。

完成后，文件位置应该是：

```text
/Users/zhang/projects/shop-app/
├── .git/
├── .dsh-preflight.json    # 这个项目使用的公司规则
├── package.json
└── src/
```

例如公司规定“超过 200 行提醒，超过 500 行不通过，超过 15 个文件提醒”，打开商城项目中的 `.dsh-preflight.json`，将前三个字段改成：

```json
{
  "warnLines": 200,
  "maxLines": 500,
  "warnFiles": 15
}
```

这里的行数是新增行数加删除行数。例如新增 150 行、删除 80 行，总变更是 230 行，会触发警告；总变更 501 行会检查失败。配置用于生成检查报告，不会自动阻止 Git 提交。

然后正常暂存准备提交的文件，在 DSH 中选择商城项目 `shop-app`，输入：

```text
/preflight
```

插件会使用当前会话选择的项目。也可以输入 `/preflight /Users/zhang/projects/shop-app`，临时指定要检查的项目。

插件会自动读取商城项目根目录的 `.dsh-preflight.json`，应用这组规则，无需再传配置路径。其他项目需要自己的规则，就在各自仓库根目录放一份配置。建议将规则文件提交到 Git，让团队共享。

**不创建这个文件也能使用插件**，此时默认超过 300 行警告、超过 800 行失败、超过 20 个文件警告。以上路径和公司规定都是示例，使用时替换成自己的实际值。

### 包含排除项的配置示例


```json
{
  "warnLines": 300,
  "maxLines": 800,
  "warnFiles": 20,
  "exclude": ["**/package-lock.json", "**/pnpm-lock.yaml", "**/yarn.lock", "**/bun.lock", "**/bun.lockb", "**/dist/**", "**/build/**", "**/coverage/**", "**/vendor/**"]
}
```

- 字段省略时采用默认值；`exclude` 一旦配置，会**替换**默认列表。`exclude: []` 将所有文件纳入检查。
- 简单 glob 支持 `*`（不跨目录）、`**`（跨目录）、`?`（单字符）；`**/` 可以匹配零层目录。不支持取反、方括号、花括号或反斜线。
- 超出阈值才触发：恰好 800 行不会因规模失败。maxLines 必须不小于 warnLines，三个数值都必须是非负整数。
- **总变更行 = 新增 + 删除**，不是净增；替换一行通常计两行，包括注释和空行，不是语法分析后的“有效代码行”。
- 被排除文件仍显示全量统计，但**不参与规模阈值，也不做内容扫描**。二进制文件计文件数，文本行数记 0 并警告无法扫描。
- 配置读取工作区当前文件，不要求暂存。公司强制政策应配合受控 CI 配置；这个本地插件不是不可绕过的合规门禁。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 输入 `/preflight` 没有这个命令 | 确认安装到正在使用的 profile，并重启原来的 DSH 进程 |
| 提示选择项目 | 在输入框上方的项目选择器中选择项目，再发送 `/preflight` |
| 检查的项目不对 | 确认当前会话选择的项目，或显式指定项目绝对路径 |
| 报告 `empty` | 确认准备提交的修改已加入暂存区；默认不检查未暂存或未跟踪文件 |
| 公司规则没有生效 | 确认文件名为 `.dsh-preflight.json`，位于被检查仓库根目录，且内容是合法 JSON |
| lint/test 脚本不存在 | 检查被检查仓库根目录的 package.json 是否定义了对应脚本 |

## 卸载插件

在终端执行后重启 DSH：

```sh
npx @deepseek-ai/dsh plugin --profile web remove dsh-plugin-commit-preflight
```

## 项目脚本的实际行为

优先读取 package.json 的 `packageManager`（npm/pnpm/yarn/bun），否则按锁文件判断，未发现锁文件使用 npm；多包管理器锁文件且无声明时显式报错。不自动调用 Corepack 或安装包管理器。脚本在 Git 仓库根目录的工作区运行；尚不支持 monorepo 子包单独选择。

默认每个脚本 120 秒，可设置 50～300000 毫秒；输出超过 1 MiB 终止；macOS/Linux 超时终止整个进程组。脚本 stdout/stderr 不返回给 AI 或写文件，避免将凭据等混进报告，详细诊断需在本地重跑返回的命令。允许的脚本名不代表内容安全：项目脚本及其 pre/post 钩子仍会执行仓库代码，可能生成缓存或文件。

**部分暂存的限制：** 行数/扫描读取暂存内容，但 lint/test 读取工作区。如果同一文件还有未暂存修改，脚本成功不能证明暂存快照成功。`git commit -a`、路径限定提交等可能改变最终提交集合，默认结果只对应检查时的 index。并发修改暂存区时应重新运行检查。内容规则是启发式文本匹配，存在误报和漏报，不是完整安全扫描。

Git 单次命令限时 30 秒、输出上限 32 MiB，超限显式报错，不静默截断。Git 外部 diff 和 textconv 均禁用。统计和扫描不修改工作区或暂存区；脚本检查的副作用见上文。
